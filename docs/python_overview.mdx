Python applications use the same graph, compiler, execution plan, and runtime
as C++ applications. The Python API is a typed authoring facade: it composes
registered C++ operators, freezes the graph into the same canonical plan, and
runs that plan through an inspectable session.

Use this section for behavior that is genuinely Python-specific. The
[Getting Started](/holoscan/sdk-user-guide/getting-started) and
[Composing Applications](/holoscan/sdk-user-guide/composing-applications/graph-composition)
tracks show C++ and Python together where their public surfaces are parallel.

## The supported authoring model

Python can author root and Python-defined reusable graphs from registered C++
operators, and it can embed reusable graph types registered by C++ providers.
It configures schema-declared parameters, wires typed ports, declares graph
policy and external scalar or inline-schema topics, compiles an immutable plan,
and controls a run session. `Tensor` values also interoperate with NumPy, CuPy,
PyTorch, and other DLPack or CUDA Array Interface producers and consumers.

Python-defined operator callbacks are not part of this surface. Implement a
new operator in C++, declare its ports, temporal contract, and parameter schema,
then register it so Python can discover and compose it. This keeps operator hot
paths and planning metadata identical across languages.

## An SDK example application shape

This example uses an illustrative independently installed operator provider.
Applications import the package that ships their operators at the same point.

```python
import holoscan as hs
from custom_holoscan.operators import BoundedSink, CameraSource, WindowFusion

graph = hs.Graph("sensor-pipeline")
camera = CameraSource(graph, "camera")
fusion = WindowFusion(graph, "fusion")
sink = BoundedSink(graph, "sink")

graph.add_flow(camera.frame, fusion.camera, queue_depth=4)
graph.add_flow(fusion.control, sink.input, queue_depth=4)
graph.set_default_clock(graph.add_clock(hs.RealtimeClock, "clock"))

plan = hs.compile(graph)
if not plan:
    raise SystemExit(plan.summary())

with hs.run_async(plan) as session:
    if not session.wait(timeout=0.25):
        session.request_stop()
        if not session.wait(timeout=5.0):
            raise TimeoutError("pipeline did not stop")
```

The `Graph` is mutable authoring state. `hs.compile()` returns an immutable
`Plan`, including rejected plans with diagnostics. A `RunSession` is the sole
owner of one run attempt; using it as a context manager guarantees cooperative
stop and join on scope exit.

## Recap

- Python and C++ author the same graph model and compile to the same plan.
- Python composes registered C++ operators and embeds registered C++ reusable
  graphs; it does not define operator callbacks in Python.
- Python-specific behavior is concentrated in this section while shared
  concepts stay in the main guide.
