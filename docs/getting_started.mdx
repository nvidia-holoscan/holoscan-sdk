Welcome to Holoscan SDK 5.0. This Getting Started track takes you from an
empty project to a running multi-rate sensor-fusion pipeline: a 60 Hz camera
and a high-rate IMU feeding a fusion operator that drives a control output.
Each chapter adds exactly one capability, and every chapter's code builds on
the previous one, so by the end you have written — not just read about — a
complete application that composes, compiles, and runs.

Two ideas come first, before you write a single operator: **errors as values**
and **time**. That ordering is deliberate. Every later API in the SDK returns
`holoscan::expected<T, Error>` instead of throwing, and every operator
declares a temporal contract that tells the runtime when it may run. Learn
those two vocabularies up front and the rest of the track reads naturally.

## Prerequisites

- **Linux** (x86_64 or aarch64).
- A **C++20 toolchain** and CMake.
- A **CUDA-capable NVIDIA GPU** — optional until the final chapter
  (Tensors 101); everything before it runs on the CPU.
- The SDK installed — follow
  [SDK installation](/holoscan/sdk-user-guide/setup/sdk-installation) first
  if you have not.

## The chapter sequence

Work through the chapters in order; each assumes the ones before it.

1. [Core concepts](/holoscan/sdk-user-guide/getting-started/core-concepts) —
   the three-phase model (compose → compile → run) and the vocabulary the
   whole guide uses.
2. [Errors as values](/holoscan/sdk-user-guide/getting-started/errors-as-values) —
   `holoscan::expected<T, Error>`, branching on `ErrorCode`, and the
   `HOLOSCAN_TRY` macro that keeps error-handling readable.
3. [Time and clocks](/holoscan/sdk-user-guide/getting-started/time-and-clocks) —
   how the runtime models time, and why every sample carries a timestamp.
4. [Your first operator](/holoscan/sdk-user-guide/getting-started/first-operator) —
   an operator as three declarations: `setup()` for structure, `contract()`
   for time, `compute()` for work.
5. [Typed parameters](/holoscan/sdk-user-guide/getting-started/typed-parameters) —
   declaring configuration with schemas so bad config fails before run.
6. [Composing a graph](/holoscan/sdk-user-guide/getting-started/composing-a-graph) —
   wiring operators together through typed ports with `add_flow()`.
7. [Compile and check](/holoscan/sdk-user-guide/getting-started/compile-and-check) —
   `compile()` turns your composed graph into an execution plan, or returns a
   rejected plan that tells you exactly why.
8. [Running and stopping](/holoscan/sdk-user-guide/getting-started/running-and-stopping) —
   starting the plan, observing it, and shutting down cleanly.
9. [Your first pipeline](/holoscan/sdk-user-guide/getting-started/first-pipeline) —
   assembling the camera + IMU fusion pipeline end to end, with its
   multi-rate temporal contract.
10. [Tensors 101](/holoscan/sdk-user-guide/getting-started/tensors-101) —
    GPU payloads: borrowing tensors from preallocated pools with
    `allocate_tensor()`, and why you never synchronize on the hot path.

<Note>
  **Why errors and time come first.** In Holoscan 5.0, failure handling and
  temporal behavior are not advanced topics — they are the calling convention.
  APIs return `expected` values you must branch on, and `compute()` never
  reasons about time because `contract()` already did. Chapters 2 and 3 give
  you those two lenses; every chapter after them assumes you have both.
</Note>
